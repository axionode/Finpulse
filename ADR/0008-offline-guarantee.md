# ADR-0008: Гарантия полной офлайновости

- Статус: Принято
- Дата: 2026-11-22

## Контекст
Приложение ни в коем случае не должно выходить в интернет и что-либо отправлять.

## Решение
1. **В коде нет сетевого стека.** Никаких сокетов, HTTP, WinHTTP, WinINet, WebView, URL-ссылок. В интерфейсе нет ссылок на сайты (даже "помощь" встроена в приложение).
2. **Проверка при сборке.** Скрипт `tools/check_imports` после линковки разбирает таблицу импорта exe (`dumpbin /imports`) и роняет сборку, если найдена любая DLL из запретного списка ADR-0001. Плюс поиск по исходникам запрещённых API (`socket`, `connect`, `WinHttp*`, `InternetOpen*`, `URLDownloadToFile`, `ShellExecute` с http).
3. **Нет автообновлений, телеметрии, аналитики, отчётов о сбоях.** Обновление = ручная замена exe.
4. **Отчёты об ошибках Windows отключены для процесса** (`WerAddExcludedApplication`), иначе Windows сама может отправить дамп памяти в Microsoft.
5. **Шрифты** только системные, загружаемые шрифты DirectWrite не используются.
6. **Брандмауэр (опция).** Команда в настройках "Запретить сетевой доступ в брандмауэре Windows" создаёт исходящее правило блокировки для Finpulse.exe (нужны права администратора, запрашиваются один раз). Это вторая линия защиты на случай чего угодно.
7. **Документ `docs/VERIFY-OFFLINE.md`:** как самому проверить, что процесс не открывает соединений (Монитор ресурсов, TCPView, правило брандмауэра).

Оговорки, которые пишем честно:
- Если пользователь сам выберет папку бэкапов внутри OneDrive/Dropbox, файл уедет в облако силами самого облачного клиента. Он зашифрован, но об этом показывается предупреждение.
- Системный диалог выбора файла (`IFileDialog`) может показывать сетевые папки: это действие пользователя, не приложения.

## Последствия
Офлайновость гарантирована конструктивно и проверяется автоматически при каждой сборке, а не только обещанием.

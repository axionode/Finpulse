# ADR-0005: Хранение данных

- Статус: Принято
- Дата: 2026-11-22
- Связано с: ADR-0004, ADR-0007, ADR-0009

## Контекст
Нужны надёжность (отключение питания не должно портить данные), скорость на десятках тысяч операций, шифрование, простой перенос на другой компьютер.

## Решение
**Движок:** SQLite через амальгаму SQLite3 Multiple Ciphers, вкомпилированную в exe.

Опции компиляции:
`SQLITE_THREADSAFE=2, SQLITE_DQS=0, SQLITE_DEFAULT_FOREIGN_KEYS=1, SQLITE_OMIT_LOAD_EXTENSION, SQLITE_OMIT_DEPRECATED, SQLITE_OMIT_SHARED_CACHE, SQLITE_ENABLE_FTS5, SQLITE_SECURE_DELETE, SQLITE_TEMP_STORE=3, SQLITE_USE_URI=0`

`SQLITE_TEMP_STORE=3` обязателен: временные таблицы в sqlite3mc не шифруются, поэтому они должны жить только в памяти и никогда не попадать на диск.

**Файлы**
```
Finpulse.exe
Finpulse Data\
  catalog.db            настройки приложения, список книг, обёрнутые ключи (ADR-0007)
  books\<uuid>.fpbook   одна зашифрованная SQLite-база на книгу
  Backups\             автоматические локальные бэкапы (ADR-0009)
  logs\                 локальный журнал без сумм и названий
```
**Портативный режим по умолчанию.** Приложение не устанавливается: данные лежат в папке `Finpulse Data` рядом с exe и создаются при первом запуске. Если папка рядом с exe недоступна для записи (например, exe положили в Program Files или на защищённый носитель), данные хранятся в `%LOCALAPPDATA%\Finpulse`, и это показано в настройках. Путь к папке данных можно поменять в настройках с переносом файлов.

**Почему отдельный файл на книгу**
- У каждой книги свой ключ шифрования, поэтому пароль книги работает как настоящее шифрование, а не как "замок в интерфейсе".
- Повреждение одного файла не задевает остальные книги.
- Экспорт/передача одной книги = один файл. Удаление книги = удаление файла.
- Цена: сводный отчёт по всем книгам открывает несколько соединений. Это дёшево.

**Надёжность**
- `journal_mode=WAL`, `synchronous=FULL` (при внезапном отключении питания последняя подтверждённая операция не теряется), `foreign_keys=ON`, `secure_delete=ON`.
- Все изменения одной пользовательской операции в одной транзакции.
- `PRAGMA quick_check` при открытии книги, полный `integrity_check` раз в неделю в фоне.
- Блокировка файла книги на время работы, чтобы два процесса не писали одновременно.

**Идентификаторы**
`INTEGER PRIMARY KEY` для скорости + `uuid BLOB(16)` (UUIDv7) для стабильных ссылок между книгами, бэкапов и будущего слияния.

**Миграции**
Версия схемы в `PRAGMA user_version`. Миграции только вперёд, каждая в транзакции. Перед миграцией делается автобэкап файла. Новая версия приложения открывает старые файлы; старая версия, встретив файл новее себя, отказывается открывать с понятным сообщением.

**Индексы (минимум)**
`lines(account_id, transaction_id)`, `transactions(date)`, `transactions(deleted_at, date)`, `lines(category_id)`, FTS5-индекс по заметкам и контрагентам.

## Рассмотренные варианты
- Свой бинарный формат: быстрее старт на 1-2 мс, но нужно самому писать журналирование и восстановление после сбоев. Отклонено.
- Одна общая база на все книги: проще сводные отчёты, но пароль книги превращается в косметику. Отклонено.
- SQLCipher: требует OpenSSL или другой крипто-библиотеки. Отклонено.

## Последствия
Надёжность уровня SQLite, шифрование страниц прозрачно для кода приложения. Схема описывается в `docs/schema.sql` на этапе разработки.

# ADR-0016: Тестирование и бюджеты производительности

- Статус: Принято
- Дата: 2026-11-22

## Решение
**Тесты (без внешних фреймворков):**
- Свой минимальный раннер тестов (макросы TEST/EXPECT, около 200 строк).
- Модульные тесты domain: деньги, округление, переполнения, парсер выражений, правила повторов, бюджеты.
- Тесты storage на временных базах: миграции со всех прошлых версий схемы, целостность, сплиты, переводы.
- Тесты crypto: обёртка/развёртка ключей, неверный пароль, повреждённые данные, тестовые векторы Argon2 и AES-GCM.
- Тест бэкапа "туда и обратно": бэкап -> восстановление в чистую папку -> побайтное сравнение данных.
- Фаззинг парсеров бэкапа и выражений суммы: `/fsanitize=fuzzer` из MSVC (часть компилятора, не библиотека).
- Debug-сборка с AddressSanitizer, Release с `/analyze` перед релизом.
- Скриншот-тесты: экраны рендерятся офскрин в PNG (WIC) на фиксированных данных, сравниваются с эталоном.

**Бюджеты производительности (на i7-6700HQ, 16 ГБ, SSD):**
| Метрика | Цель |
|---|---|
| Холодный старт до стартового экрана | ≤ 250 мс |
| Открытие книги после ввода PIN (без учёта Argon2) | ≤ 100 мс |
| Проверка PIN (Argon2id) | около 150 мс |
| Добавление операции до обновления экрана | ≤ 16 мс |
| Любой отчёт, 100 000 операций | ≤ 50 мс |
| Прокрутка списка, 100 000 операций | без пропуска кадров |
| Память в простое | ≤ 40 МБ |
| CPU в простое | 0% |
| Размер exe | ≤ 4 МБ |

`bench.cmd` генерирует книгу на 100 000 синтетических операций и проверяет бюджеты. Регрессия бюджета = провал сборки на CI.

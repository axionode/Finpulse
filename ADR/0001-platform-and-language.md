# ADR-0001: Платформа, язык, компилятор, зависимости

- Статус: Принято
- Дата: 2026-11-22

## Контекст
Требования: Windows 10 и 11, максимальная скорость, минимум памяти и CPU, никаких лишних библиотек, работа напрямую с API Windows, без интернета. Тот же принцип, что у MediaSense: нативно, без посредников, один самодостаточный exe.

## Решение
- Язык: C++20. Компилятор: MSVC из Visual Studio 2022 Build Tools (или полной VS 2022). Архитектура: x64. ARM64 позже, если понадобится (код это позволяет).
- API: чистый Win32 + COM-интерфейсы Windows SDK. Никаких фреймворков (MFC, ATL, Qt, WinUI, .NET).
- Рантайм: статический CRT (`/MT`). На выходе один `Finpulse.exe`, не нужен VC++ Redistributable.
- Минимальная ОС: Windows 10 1809 (build 17763). Возможности новых сборок включаются по факту наличия (Mica только Win11 22H2+, исключение окна из захвата экрана с Win10 2004+).
- Флаги сборки Release: `/O2 /GL /LTCG /permissive- /W4 /WX /utf-8 /sdl /guard:cf /Qspectre`, линкер `/DYNAMICBASE /NXCOMPAT /CETCOMPAT /OPT:REF /OPT:ICF`. RTTI выключен. Исключения C++ не используются, ошибки через собственный `Result<T>`.
- COM-указатели через `Microsoft::WRL::ComPtr` (это заголовок из Windows SDK, не внешняя библиотека).

### Разрешённые сторонние исходники (вендорятся в third_party, компилируются в exe)
1. **SQLite3 Multiple Ciphers** (sqlite3mc), лицензия MIT. Один файл-амальгама: SQLite + шифрование страниц, без внешних зависимостей (OpenSSL не нужен).
2. **Argon2** (эталонная реализация), лицензия CC0/Apache-2.0. Около 1000 строк C, нужен для вывода ключа из PIN и пароля бэкапа.

Больше ничего. Любая новая зависимость требует отдельного ADR.

### Системные DLL, которые разрешено импортировать
`kernel32, user32, gdi32 (минимально), d2d1, dwrite, d3d11, dxgi, dcomp, dwmapi, uxtheme, shcore, imm32, ole32, oleaut32, shell32, shlwapi, comdlg32, windowscodecs, bcrypt, crypt32, wtsapi32, wer, advapi32, ncrypt (опц.)`

Запрещено импортировать (проверяется при сборке, см. ADR-0008): `ws2_32, wsock32, winhttp, wininet, urlmon, iphlpapi, dnsapi, webservices, mswsock, rasapi32`.

## Рассмотренные варианты
- **C# + WPF**: быстро писать, но .NET-рантайм, 80-150 МБ RAM, старт 0.5-1 с. Противоречит требованию.
- **WinUI 3**: зависимость от Windows App SDK, тяжёлый, плохо работает без упаковки, на Win10 хуже.
- **Rust + windows-rs**: хороший вариант по безопасности памяти, но тянет крейты, а вся экосистема SQLite/крипто там через сторонние пакеты. Отклонено ради единообразия с MediaSense и минимума зависимостей.
- **Electron / Tauri / WebView2**: веб-движок внутри, сотни МБ памяти, сетевой стек в процессе. Отклонено.
- **Qt**: огромная библиотека, лицензирование. Отклонено.

## Последствия
- Плюсы: старт за десятки миллисекунд, 20-40 МБ RAM, exe 2-4 МБ, ноль внешних рантаймов.
- Минусы: весь UI пишем сами (ADR-0002), больше кода. Риск ошибок работы с памятью закрываем RAII, ASan в debug, фаззингом парсеров (ADR-0016).

# ADR-0018: Уточнения по итогам реализации версии 0.1

- Статус: Принято
- Дата: 2026-11-22
- Уточняет: ADR-0001, ADR-0002, ADR-0007, ADR-0012, ADR-0014

## Контекст
При написании первой рабочей версии часть решений оказалось разумнее реализовать иначе, чем было записано. Принятые ADR не переписываются задним числом, поэтому отличия собраны здесь.

## Решения

1. **Интерфейс: immediate-mode вместо дерева виджетов (уточняет ADR-0002).**
   Экраны описываются функциями, которые рисуют и обрабатывают ввод за один проход. Состояние виджетов (фокус, курсор в поле, анимации, прокрутка) хранится в контексте по идентификатору. Кадр рисуется только при вводе или анимации, в простое CPU 0%. Кода примерно вдвое меньше, чем с деревом виджетов, скорость та же.

2. **Рендер без DirectComposition (уточняет ADR-0002).**
   D3D11 + DXGI flip-model swap chain + Direct2D device context напрямую к окну. DirectComposition понадобится только для фона Mica на Windows 11; Mica отложена.

3. **Доступ к базе в UI-потоке (уточняет ADR-0012).**
   Запросы к SQLite короткие (единицы миллисекунд), поэтому выполняются в UI-потоке, отдельного потока данных пока нет. Вывод ключа из PIN (около 150 мс) и экспорт тоже синхронные. Вынести в поток, если замеры на больших данных покажут задержки.

4. **Сборка выпускного exe (уточняет ADR-0001, ADR-0014).**
   Выпускной `Finpulse.exe` собирается кросс-компилятором MinGW-w64 (GCC 13, статическая линковка, импортирует только системные DLL). Сборка в MSVC поддерживается через `build.cmd`, но в этой среде не проверялась. Исключения и RTTI выключены в обоих вариантах.

5. **Копия обёрнутого ключа в файле книги не сделана (уточняет ADR-0007).**
   Обёрнутые ключи лежат только в `catalog.db`. Переезд и восстановление идут через `.fpbackup`, где ключи есть. Автобэкап при выходе включает и каталог, и книги.

6. **Формат `.fpbackup` (уточняет ADR-0009).**
   Внутри лежат файлы книг как есть (зашифрованные своим ключом) плюс записи каталога. Ключи книг включаются, если книга без PIN, открыта или PIN введён в диалоге экспорта. Книга без ключа в бэкапе восстанавливается только со своим PIN. Режимы шифрования файла: без пароля, пароль (Argon2id 64 МБ, 3 прохода → AES-256-GCM блоками по 1 МБ), DPAPI (для автобэкапов). AAD ключа книги не привязан к uuid, чтобы копия при импорте сохраняла PIN.

7. **Сбои.**
   Системный диалог отчёта об ошибке отключён (`SetErrorMode`), вместо него локальное сообщение. Процесс исключён из Windows Error Reporting. Данные не теряются благодаря WAL и `synchronous=FULL`.

8. **Отладка ввода.**
   Файл `debug-input.flag` рядом с exe включает журнал мыши `debug-input.log`. По умолчанию выключено.

## Последствия
Поведение для пользователя совпадает с ADR. Отложено: Mica, отдельный поток данных, копия ключа рядом с книгой, проверка сборки в MSVC.
